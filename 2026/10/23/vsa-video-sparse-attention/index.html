VSA 实现详解：三维分块、均值路由与块稀疏 Attention

发表于 2026-10-23 分类于 深度学习 阅读次数： 本文字数： 20k 阅读时长 ≈ 1:14

VSA（Video Sparse Attention）先把视频 token 按 (T,H,W) 时空邻域分块，对每块的 Q、K 分别求均值，再用两个均值向量的点积决定保留哪些区块连接。选块完成后，正式 attention 仍用原始 Q/K/V 计算。

下文默认读者熟悉 FlashAttention，按“全量 Q/K → 分块均值 → 小 S → 每块 TopK → 稀疏 attention”的顺序讲。例子固定为 (T,H,W)=(4,4,4) 的 64 个 token 切成四个 (4,2,2) 区块，同一批 token 会依次经过池化、选块和 GPU 读取。

先看完整计算顺序

先为所有 token 生成完整的 Q、K、V；把 Q、K 按块分别平均成小 Q、小 K，视频按三维邻域分块；两者相乘得到小 S；每个视频 query 块按小 S 选 TopK；再用原始 Q/K/V 计算选中连接的 attention。

上图省略 batch 和 head 维；N 是 token 数，J 是块数。“全量 Q/K”指完整的向量序列，不必先算出 N×N 的完整 QKᵀ。下文把小 S 记作路由矩阵 E，以区别于正式 attention 的 token 级 logits。

一个“视频组”就是同一 query 块。块内的 token 共用一组选中的 KV 块，各 token 的权重仍分别计算；选块由当前 Q/K 决定，可随 head、层和去噪步变化。参与选择的是 query block，不是 value 张量 V。Context 的全连接与 R2V 的分组规则见第 5.3 节。

1. 先理解 (T,H,W) 分块：一个块包含哪些 token

T、H、W 是模型中视频 token 网格的时间、高度和宽度，已经过编码和 patch 化，不能直接当作原视频的帧数与像素尺寸。为避免与高度 H 混淆，下文用 h 表示 attention head 数，D 表示每个 head 的维度。

设 token 网格为 (4,4,4)，分块大小为 (4,2,2)：

一个块跨越四个时间位置，在每个时间位置覆盖同一个 2×2 空间窗口。四个块分别命名为 A、B、C、D：左上、右上、左下、右下。

数字是原始 token 编号；同一种颜色跨四个时间切片构成一个 (4,2,2) 块。蓝色 A 共 16 个 token。文中图表都用教学数据，编号直接显示在格子中，颜色表示区块归属。

例如 A 的范围为 t=0…3、y=0…1、x=0…1。按 x 最快、y 次之、t 最慢展平，原始编号为：

所以，“三维相邻的一块”在原始序列中通常分散在多个位置。直接把序列每 16 个连续 token 分成一组，会得到一个完整的时间切片，几何含义完全不同。

一般地，块大小为 (bT,bH,bW) 时，完整块容量 M=bT×bH×bW，块数为：

J=⌈TbT⌉⌈HbH⌉⌈WbW⌉J=\left\lceil\frac{T}{b_T}\right\rceil\left\lceil\frac{H}{b_H}\right\rceil\left\lceil\frac{W}{b_W}\right\rceilJ=⌈bT​T​⌉⌈bH​H​⌉⌈bW​W​⌉

边缘块可能少于 M 个 token，要单独记录真实长度 nᵢ；这会同时影响池化分母和正式 attention 的有效 key 范围。

这里用 (4,2,2) 展示三维池化，便于逐个标注 token。它是教学几何；FastVideo H3 后端支持 64、128、256-token 块，具体配置见第 5 节。

2.3 均值为什么有效，又可能漏掉什么

由点积的线性性质：

qˉiTkˉj=1ninj∑a∈i∑b∈jqaTkb\bar{\mathbf q}_i^{\mathsf T}\bar{\mathbf k}_j=\frac1{n_i n_j}\sum_{a\in i}\sum_{b\in j}\mathbf q_a^{\mathsf T}\mathbf k_bqˉ​iT​kˉj​=ni​nj​1​a∈i∑​b∈j∑​qaT​kb​

它刻画的是两个区块间的平均匹配。相邻时空位置的特征如果较接近，一份共享路由就可能代表整块的主要需求。

但平均会稀释局部强匹配。例如一个 query 块中的两个一维向量为 [10,-10]，均值为 0；对 keys [10,10]，路由分数为 0，第一个 query 的两个 token 点积却都是 100。块内不同 token 的需求可能被均值掩盖，这种偏差要靠训练适配和质量验证来弥补。

3. pack：让同一块的 token 在内存中连续

三维分块规定“哪些 token 属于同一块”，pack 则把这些成员实际排到一起，方便 kernel 读取。回到前面同一组编号：

例如 A 会变成 packed 序列的前 16 个位置：

随后是 B 的 16 个，再是 C、D。Q/K/V 使用同一张位置映射；若位置编码已进入 Q/K，重排移动的是已有向量，不会为 packed 位置重新分配原始时空坐标。

池化和 pack 在数学上都可以直接按几何索引完成。工程里常先 pack 成 [J,M,D]，再沿 M 求均值，让路由和主计算共用一份布局。所以按几何索引理解选块规则就够了；实现里先重排再选块，只是为了复用同一份布局。

输出必须按逆映射放回去。例如 packed 位置 2 存放原 token 4 的结果，最终就写回输出序列的第 4 个位置。padding 输出被丢弃，所有有效 query 都有输出。

5. H3 的 sequence 布局：从多模态序列到块序列

FastH3 是基于 MiniMax-H3 的音视频生成模型，它的 attention 同时处理文本、条件图像、音频和视频。读 VSA kernel 之前先分清三点：模态在原始 sequence 中的顺序、token 被重排到哪个块、张量的维度排列。

5.1 原始 packed sequence：多种模态共同做 attention

常见输入是 [文本 | 条件关键帧 | 音频 | 生成视频]。带参考视频的任务会多出视频区域，具体顺序由调用方传入的 segments 决定。H3 模型用 text_indices、video_indices、audio_indices 把各模态 embedding 写入同一条序列，并携带各 token 的位置和模态信息。

这层 attention 是联合双向的：视频 query 能看音频、文本，非视频 query 也能看视频，没有语言模型解码时的 causal 三角限制。模型组装入口

5.2 VSA tiled sequence：dense prefix 在前，视频块在后

metadata builder 接收有序的 segment 描述：整数表示一个 dense segment 的 token 数，三元组表示一段视频的 (T,H,W) 网格。随后执行两类分块：

  • 文本、音频、参考图片按一维连续 token 切块；不同 segment 不拼进同一个块，末块单独 padding。
  • 参考视频和目标视频分别按三维窗口切块，再把块内成员排成连续序列；每段视频保留独立的块范围。

所有 dense chunks 排到前面，形成 prefix；视频区域依次跟在后面，目标视频是最后一个区域。prefix 在这里只指计算布局中的前缀，不表示“只包含文本”或“只能被单向访问”。

5.3 从 attention 矩阵看普通生成与 R2V

先看不含参考视频的情况，sequence 为 [Context | OutputVideo]。Context 指文本、参考图片、音频等 dense prefix；横轴是 key，纵轴是 query。

Context query 看全局，OutputVideo query 保留全部 Context keys，只对 Video keys 做 sparse attention，因此只有矩阵右下角需要 TopK：

标有 ▸ 的 O1 行保留了 C0、C1，以及小 S 中分数最高的两个视频块 O1、O4。每个实心格内部仍执行完整的 token 级 QK、softmax、PV，空格对应的块计算被跳过。mask 可以不对称，也没有 causal 三角限制。

R2V：每段参考视频都是一个独立的候选组

R2V（Reference-to-Video）把参考视频作为条件输入。假设有两段参考视频，tiled sequence 为 [Context | RefVideo 1 | RefVideo 2 | OutputVideo]。所有视频 query 块共用一个小 S，但选块沿 key 轴分组，在每组内部单独取 TopK：

O1 行保留全部 Context，再从 Ref 1 选 R1、从 Ref 2 选 S2、从输出视频选 O0 和 O3，共 6 个 KV 块。参考组的配额独立保留，即使输出视频的分数整体更高，也不会挤掉参考组的名额。选完后，正式 attention 在这些保留 keys 的并集上做一次 softmax 归一化，不是各组分别归一化再相加。

6.5 一轮计算中，各组 warp 究竟做了什么

Warp 0–7：每线程一行，生成指数权重与归一化统计

四个 warp 共 128 个线程，正好覆盖一个 Q 块的 128 行。源码中 m_tile = warp_id < 4 ? 0 : 1，sm_tid = (warp_id & 3) * 32 + lane。每个线程负责一个 query 行，在每轮读取该行的 128 个 logits，在寄存器中完成 mask、行最大值与行和计算；不是四个 warp 合作归约同一行。

它先等待 full_bar_spo，通过 tcgen05.ld 把 S 从 TMEM 读到 s_regs[128]。这里 S 是尚未乘 sm_scale 的 QK 点积。用源码的缩放约定，令 γ=sm_scale × log₂(e)，一轮状态更新可写为：

α=2(m−m′)γ,P~=2(S−m′)γℓ′=αℓ+rowsum⁡(P~)U′=αU+P~V,O=U/ℓLSE2=mγ+log⁡2ℓ\begin{aligned} \alpha&=2^{(m-m')\gamma},\qquad \widetilde P=2^{(S-m')\gamma}\\ \ell'&=\alpha\ell+\operatorname{rowsum}(\widetilde P)\\ U'&=\alpha U+\widetilde P V,\qquad O=U/\ell\\ \mathrm{LSE}_2&=m\gamma+\log_2\ell \end{aligned}αℓ′U′LSE2​​=2(m−m′)γ,P=2(S−m′)γ=αℓ+rowsum(P)=αU+PV,O=U/ℓ=mγ+log2​ℓ​

0–7 负责前两行中的指数与行统计，不负责 U 的缩放或 P~ V\widetilde{P}\,VPV 矩阵乘。P~\widetilde{P}P 没有除以 ℓ。线程在 FP32 中累加行和，把 P~\widetilde{P}P 转成 BF16 写入 TMEM，供后续 MMA 消费。当前配置还混用硬件 exp2 与软件近似指数路径，以调整指数计算的执行压力。指数与权重写出

源码的 m′ 也不一定每轮都更新为最新最大值：先求候选最大值，再检查旧参考值到新值的变化；若 acc_scale >= -8，沿用旧 m、令 α=1。随后 P~\widetilde{P}P 和 ℓ 都按这个参考值计算，省去部分输出缩放。空 key 和短行补轮通过有效长度 mask 排除；所有保留的 prefix/video keys 共用同一行统计。

LSE 是循环结束后的可选输出：tile128 由这组 warp 写出 m_run * scale_log2 + log2(l_run)。need_lse=False 只省掉 LSE 写出，P~\widetilde{P}P、m、ℓ 的计算仍然需要。指数近似、BF16 舍入与参考值更新策略属于数值实现细节，不能据上述公式宣称与理想实数计算逐位一致。

Warp 8–11：修正 U，再完成最终归一化

这四个 warp 共 128 个线程，依次服务 Q₀、Q₁ 的 128 行。等待 full_bar_alpha 后，从 shared memory 读取 α；若一个 warp 内全部 α=1，就跳过该 warp 对应行的缩放，否则用 tcgen05.ld/st 读写 TMEM 中的 FP32 U，执行 U ← αU。

每轮由 Tensor Core 累加的是 P~ V\widetilde{P}\,VPV，8–11 负责的是累加器的尺度修正。最后一轮，它们等待 full_bar_o_acc 与 full_bar_l，取最终 ℓ，用倒数乘法完成 O=U/ℓ，转换为 BF16 并写入 shared-memory 输出缓冲，再通知 epilogue。全部 keys 被屏蔽的行使用零缩放因子，输出为零。correction 与最终归一化

Warp 12：提交指令，由 Tensor Core 计算

elect_one_sync() 从 MMA warp 中选出一个线程，由它发射 tcgen05.mma。QK 读取 shared memory 中的 Q/K，结果写入 TMEM 的 S；P~ V\widetilde{P}\,VPV 读取 TMEM 的 P~\widetilde{P}P 和 shared memory 的 V，累加到 TMEM 的 U。一个 tile 由多条 MMA 指令完成，warp 还要推进描述符、等待 barrier，并提交完成通知。

这里的单线程是指令发射粒度，矩阵乘加由 Tensor Core 硬件执行；warp 0–7 则要逐项执行指数、比较、求和与数据转换。因此不能用“softmax 8 个 warp、MMA 1 个 warp”比较两部分的计算量。MMA 指令序列、tcgen05 发射语义

SPLIT_P 与 barrier：权重就绪和累加器可写是两件事

当前配置启用 SPLIT_P：每行 128 个 BF16 权重打包为 64 个 32-bit 单元。0–7 先写前 48 个单元，即 96 列 P~\widetilde{P}P，通知 empty_bar_spo；再写剩余 16 个单元，即 32 列，通知 full_bar_p_last。MMA 可以先消费前一段，推进到最后 32 列时才等待后一段就绪。

稳态下的 empty_bar_spo 不是只由 softmax 一方触发：它汇合该 Q 块的 128 个指数/统计线程与 128 个 correction 线程。这同时保证“P~\widetilde{P}P 前段已写好”和“旧 U 的缩放已完成”，随后才能安全开始本轮 P~ V\widetilde{P}\,VPV。首轮通过初始化提供 correction 侧的就绪信号，因为还没有旧 U 需要缩放。

同步点 约束的数据依赖
full_bar_spo QK 结果已可供 0–7 读取
full_bar_alpha 本轮缩放信息已发布，8–11 可以修正 U
empty_bar_spo P~\widetilde{P}P 前段与 U 均已准备好，允许 MMA 继续
full_bar_p_last P~\widetilde{P}P 尾段已准备好，允许完成剩余 PV
full_bar_o_acc + full_bar_l 最终累加器和分母都已就绪，允许归一化

这些 barrier 随轮次切换 phase；共享位置可以反复使用，而不会把上一轮的完成信号当成下一轮。分段写入、PV 尾段等待

Warp 14、13、15：加载、写回与跨工作项衔接

Load warp 14 为 Q₀、Q₁ 分别读索引；每次由 32 个 lanes 预读一个索引窗口，再用 shuffle 取得当前块号。它等待空槽后提交 TMA load，硬件完成搬运后满足 full barrier，MMA 才能读取。tile128 的 KV ring 是 3 个 32 KiB 槽，分别承接 K 或 V 搬运，并非三份完整 K/V。Q 使用独立缓冲；短行越界轮次夹取最后一个有效索引，空行取安全块号 0，再由 0–7 全部 mask 掉。

Epilogue warp 13 等待 O 在 shared memory 中就绪后提交 TMA store，并等待源数据已被读取，再释放对应输出槽位。它不重新计算归一化。

Scheduler warp 15 通过 CLC（Cluster Launch Control）尝试取消同一次 launch 中尚未执行的 CTA，并取得其工作编号。各角色消费同一份 CLC 响应，更新局部 workitem_id，继续处理下一对 Q；原 CTA 的 blockIdx 不变，也没有再次请求 CPU launch。缓冲区的 full/empty barrier 约束前后工作项的重叠，而非要求所有 warp 同步退出再重启。加载与工作项推进、写回与 CLC 调度

6.6 相比 dense kernel，收益从哪里来

与现代 dense FlashAttention 相比，新增收益主要来自缩短 KV 遍历集合。TMA、Tensor Core、在线 softmax、warp 分工本身也可以用于 dense kernel，不能把它们全算成 VSA 独有的收益。

层面 dense attention 此稀疏路径
KV 遍历 对双向 attention 遍历全部 key blocks 按每个 Q 块的索引列表读取
QK / PV 每个候选块都做矩阵乘 跳过未选块的主计算
KV 搬运 为全部候选块搬运数据 通常随选中块减少，双 Q 块补轮有额外开销
中间矩阵 FlashAttention 已避免把完整 N×N 矩阵写回显存 延续相同的融合思路
负载 每行遍历长度较一致 prefix dense、视频 sparse；需要独立计数与调度
额外成本 无 VSA 路由 pool、TopK、pack、索引转换及 padding

CLC（Cluster Launch Control）让完成当前工作的 CTA 获取尚未执行的工作项，帮助处理长度不齐的工作负载；它不会消除同一 Q 块对内部的补轮。吞吐还受数据复用、带宽、占用率和边缘块比例影响，不能只看一个稀疏率。

7. 收益与代价：看配对数量，也看实际质量

对完整等大块，N=MJ，每个 query block 保留 R 个 key blocks。忽略 batch 和 head，参与计算的配对数：

计算 配对数量 开头的小例子：M=16、J=4、R=2
dense QK N² 4,096
pooled 路由 J² 16
主稀疏 QK J×R×M² 2,048

这个例子里，主 QK/PV 保留约一半工作量；路由点积数量是 dense 的 1/M²。这个比值只描述数学规模，实际耗时还包括 pool、TopK、pack、索引转换和访存。

块越大，路由矩阵越小，却会为局部重要 token 连带计算更多连接；块越小，选择更精细，但路由和调度成本增加。边缘块、dense prefix 也会改变实际保留比例，不能把块数比例直接当成端到端加速比。

质量同样要单独验证。若保留集合覆盖了某行 dense 概率的比例 c，令 O_kept、O_drop 分别为两组归一化后的输出，则在 0<c<1 时：

Odense=cOkept+(1−c)OdropOsparse=Okept\begin{aligned}O_{\mathrm{dense}}&=cO_{\mathrm{kept}}+(1-c)O_{\mathrm{drop}}\\O_{\mathrm{sparse}}&=O_{\mathrm{kept}}\end{aligned}Odense​Osparse​​=cOkept​+(1−c)Odrop​=Okept​​

误差既取决于舍弃的概率质量，也取决于两组 V 的差异。评估时要把这几项分开：路由覆盖率、attention 输出误差、完整视频质量，以及拆分耗时与端到端延迟。
